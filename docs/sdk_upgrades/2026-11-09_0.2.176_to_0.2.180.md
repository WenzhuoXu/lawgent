# claude-agent-sdk 0.2.176 → 0.2.180 (Claude Code 2.1.316 → 2.1.321)

Reviewed 2026-11-09. Source: `python scripts/agent_sdk_changes.py --to 0.2.180`
(SDK notes, SDK commits and files, and the whole CLI changelog for 2.1.317,
2.1.318, 2.1.319 and 2.1.321 — 2.1.320 was not released). Every item was read;
the ones below matter to this setup (headless SDK session per chat turn,
`resume` per chat, `dontAsk` with an allowlist, `setting_sources=[]`, the
in-process `legal` MCP server behind ToolSearch, Bash, WebFetch, Read,
foreground sub-agents, subscription login). The rest is the desktop app,
cloud and self-hosted sessions, the apps gateway, Remote Control, VS Code,
Windows, Chrome and the TUI.

SDK Python layer: one change, `HookMatcher(on_failure=...)`. Dependencies
unchanged.

## Fixes for problems we hit or can hit

- **A turn ended with "API Error: EPROTO: The TLS handshake failed" when the
  connection broke mid-reply** (regression since 2.1.302, so in 2.1.316). Now
  the partial reply is kept or the request retried. (2.1.321)
- **A call to an MCP tool before it is loaded now returns its input schema.**
  On 11-05 the model called `legal_fetch` twice with invented arguments
  (`id`, `label`, `source_id`) before ToolSearch had loaded it. (2.1.318)
- **WebFetch passed "No response from model" to Claude as page content** when
  its page-reading model returned nothing; now a clear error. (2.1.321)
- **Bash commands sent together could run in the wrong folder** when an earlier
  one changed folders. (2.1.321)
- **SDK sessions hung, and new messages were not saved, when memory ran out
  while the transcript was read.** Long chats reach 300–450K tokens. (2.1.321)
- **`--continue` lost the earlier conversation after a malformed tool call's
  retries ran out** (regression in 2.1.314; we resume every turn). (2.1.318)
- **Idle compaction could replace a conversation with a reply that was not a
  summary**; **very long conversations lost their earlier summary** when
  compaction shortened its own request. (2.1.318, 2.1.317)
- **Resumed sessions** were told again about a file change, and sometimes
  stopped using a built-in tool after an earlier failed call. (2.1.317)
- **Read under-counted a PDF's pages from its own metadata**; **Grep/Glob
  results cut by a time limit were treated as complete**; **Write ended the
  turn as a refusal when it could not read the file to overwrite**. (2.1.317,
  2.1.319)
- **Text dropped from informational messages sent to SDK clients**; **a
  generic exit-code error instead of the run's own error on a full disk**.
  (2.1.319)
- Security: several Bash permission-check bypasses (crafted environment
  prefix, quoted words in deny rules, `sed`, a read-only command running
  outside the sandbox, `cp`/`mv` into a directory, a write judged from the
  wrong folder). Bash is on our allowlist. (2.1.319, 2.1.321)

## New capabilities we can use

- **Login expiry is visible.** `claude auth status` reports `loginExpiresAt`
  (2.1.318); the first check on 2.1.321 showed the claude.ai login used by
  this server ends **2026-11-29T18:35Z**. When it ends every `claude_code`
  turn fails. `scripts/agent_sdk_check.py` prints it; it belongs in the serve
  start-up check and the usage panel.
- **Billing fallback warning** (2.1.319): when the claude.ai login ends and an
  `ant auth login` sign-in exists, Claude Code continues on it and bills the
  Console organisation. `runtime.subprocess_env` blanks `ANTHROPIC_API_KEY`
  but not that sign-in; watch the session's `apiKeySource`.
- **`HookMatcher(on_failure="block")`** (SDK 0.2.177): a PreToolUse hook could
  enforce what the prompt only asks — no spoofed User-Agent in `curl`, no
  writes outside the chat folder — and fail closed.
- **`CLAUDE_CODE_DISABLE_FEATURE_FLAGS`** (2.1.319): stops remote feature-flag
  fetching so behaviour changes only with a version we chose. Not turned on:
  it also freezes fixes delivered by flag; consider if behaviour drifts between
  upgrades.
- `permissions.denyInsteadOfPrompting` (2.1.319): not needed, `dontAsk`
  already denies.
- Claude Fable 5.2 (`claude-fable-5-2`, 1M context, $8/$40) is available; not
  offered here (model changes follow the parity checklist in CLAUDE.md).

## Behaviour changes to verify

- **Old transcripts are now cleaned up for runs with `--setting-sources`**
  (2.1.317) — ours. Claude Code deletes transcripts older than
  `cleanupPeriodDays` (default 30): a chat resumed after that falls back to a
  fresh session with the digest (`claude_code_resume_failed`). Expected, not
  harmful; it also stops `~/.claude/projects` growing without bound.
- The Read tool's "file unchanged since your last Read" stub is gone (2.1.317):
  re-reads return the content again, which costs context on long chats.
- Sub-agents on another model take that model's effort (2.1.317): ours are
  `model="inherit"` with an explicit effort, so unaffected (tested).
- A web or shell call that would send the account e-mail together with a
  User-Agent is refused in `dontAsk` (2.1.317, narrowed in 2.1.321).
- Background command notifications are cut to start and end (2.1.321): we run
  no background tasks.
